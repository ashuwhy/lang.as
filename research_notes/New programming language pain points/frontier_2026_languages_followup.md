## 1. GitHub Octoverse 2025

### Takeaway
The Octoverse 2025 headline figures are SNIPPET-CONFIRMED: TypeScript #1 on GitHub by monthly contributors in August 2025 (2,636,006; +66.6%; about 42k ahead of Python), 180M+ developers, 36M+ new in a year, 1.1M+ public repos importing an LLM SDK. The "94% of LLM compilation errors were type-check failures" figure traces to **Mündler, He, Wang, Sen, Song and Vechev, "Type-Constrained Code Generation with Language Models", PLDI 2025 (PACMPL vol. 9, issue PLDI, pp. 601–626; arXiv 2504.09246)**. The 94% is measured on TypeScript generated by open-weight models of 2B–34B parameters, not on LLM code in general. The GitHub page that states it is the follow-up post "Why AI is pushing developers toward typed languages" (Cassidy Williams, about January 2026), which calls it "a 2025 academic study".

### Inferences
- The 94% figure is narrower than GitHub's framing suggests. It is the share of *compilation errors* (not of all bugs) in TypeScript generated by open-weight models of 2B–34B parameters on the paper's benchmarks. It says type errors dominate what a compiler catches in LLM output. It does not say typed languages reduce overall defects, which remains the unverified assumption flagged in `developer_complaints.md`.
- The same paper shows a language-side fix works: constraining decoding with the type system halves compile errors. For a new language, a type system simple enough to drive constrained decoding is a concrete, evidence-backed design goal.
